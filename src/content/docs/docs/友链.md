## 概述

友链页（`/friends/`）是「好友卡片墙」：主数据来自 `friends` [集合](/docs/内容/友链/) （一个 `.md` = 一个友链），页面底部再合入 `tombstones`（墓碑）集合，并挂一个评论区。

- **展示页面**：`src/pages/friends.astro`
- **卡片组件**：`src/components/features/FriendCard.astro` + `src/styles/components/friend-card.css`
- **页面样式**：`src/styles/pages/friends.css`（网格 / 区块标题 / 墓碑）
- **悬浮预览**：`src/styles/components/friend-preview.css` + `friends.astro` 内联脚本
- **集合定义**：`src/content.config.ts` 的 `friendsCollection` / `tombstonesCollection`
- **字段与录入规范**：见《[友链](/docs/内容/友链/)》内容文档

> 页面挂载了「签写」动效大标题（`PageTitle`），且属于**无侧栏页面**（不显示左右侧栏，内容区放宽）。

***

## 一、页面结构（`friends.astro`）

自上而下依次是：

1. **`PageTitle`**：标题 / `eyebrow="Friends"` / 描述「志同道合的朋友们」。
2. **「添加友链」按钮**：点击由 `slot="head"` 内联脚本平滑滚动到评论区（找 `.comment-container, #waline, #tcomment, .giscus`）。页面下方还会渲染 `spec` 集合的 `friends` 条目正文（Markdown）与评论区（`customPath="/friends/"`）。
3. **新朋友区**：最近添加的 3 个。
4. **我的朋友们**：`group: friend`。
5. **更多伙伴**：`group` 缺省或 `other`。
6. **友链墓碑**：`tombstones` 集合（`title` / `avatar` / `note`），目录为空时不调用 `getCollection`、区块自动隐藏。
7. **正文 Markdown + 评论区**。

### 排序与分区规则

1. 过滤 `enabled: false`；
2. **新朋友**：按 `added` 降序取前 3，独立置顶，并从下面两个分组中排除（避免同一站点出现两次）；
3. `group: friend` → 「我的朋友们」，缺省 / `other` → 「更多伙伴」；
4. 各分组内按 `weight` 降序排列。

> ⚠️ **禁止用文件 mtime 做排序兜底**：CI（EdgeOne / GitHub Actions）每次全新 clone，所有文件 mtime 都等于构建时刻、比任何业务日期都新，会让缺 `added` 的旧友链永远霸占「新朋友」区块（2026-09 线上事故根因）。排序只认 frontmatter 的 `added`；缺字段时构建期 `console.warn` 并落到最后。

### 网格布局（`friends.css`）

- 桌面：`repeat(auto-fill, minmax(13rem, 1fr))`——4/5 宽度下宽屏约 5 列；
- 移动端（≤768px）：`minmax(9.5rem, 1fr)`。

## 二、友链卡片（2026-09-30 改版）

卡片换成\*\*「圆角头像（44px 圆角方块）+ 名字」一行\*\*：

- **去掉了**卡片的截图背景 / 描述 / 域名 / 状态徽标与卡片外框；
- 悬浮只留**极淡底色**（`--btn-plain-bg-hover`）+ 名字染主题色（`--primary`）；`focus-visible` 显示主题色虚线框；
- 名字单行省略（`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`），`desc` 只作 `title` 提示；
- 尊重 `prefers-reduced-motion`（关过渡）。

页面宽度同时从 932px 放宽到**视口 4/5**（`src/styles/features/no-sidebar-pages.css` 的 friends 段，≥1280px 为 `80vw`）。

### 卡片交互（`friends.astro` 内联脚本）

单例守卫 `window.__friendCardReady`，由 `astro:page-load` / `swup:content:replaced` 驱动重新绑定：

- **整卡点击**：事件委托，读 `data-href` 新窗口打开（`noopener,noreferrer`）；键盘 `Enter` / `Space` 同样可触发；头像 overlay 链接优先。
- **头像懒加载**：`IntersectionObserver`（`rootMargin: 200px`）把 `data-src` 写入 `src`；`load` 成功加 `.is-loaded`，失败或 **5s 超时**加 `.is-error`（显示 CSS 涂鸦占位）。
- **鼠标跟随光晕**：`mousemove` 委托到 `[data-friends-grid]`，写 `--mouse-x` / `--mouse-y`。

### ⚠️ 必须保留的类名与 data 属性（脚本 / 外部程序依赖）

| 位置                                         | 标识                            | 消费方                                               |
| ------------------------------------------ | ----------------------------- | ------------------------------------------------- |
| `.friend-card`                             | `data-href`                   | 页面脚本：点击 / 键盘打开                                    |
| `.friend-card`                             | `data-screenshot`             | 页面脚本：悬浮预览 `#friend-preview`                       |
| `.friend-card`                             | `data-title` / `data-siteurl` | **朋友圈抓取程序**（见第四节）                                 |
| `.friend-card-avatar` / `__face` / `__img` | `data-src`                    | 头像懒加载 + 涂鸦 fallback；`__img` 的 `data-src` 亦为朋友圈抓取点 |

改卡片结构 / 类名 / friends 字段时，务必逐一确认这些标识仍在。

## 三、悬浮站点截图预览（`#friend-preview`，保留功能）

**这是站长明确要求保留的功能**，卡片上的 `data-screenshot` 触发，不随 2026-09-30 卡片改版删除（`friend-preview.css` 与 `friends.astro` 预览脚本均未改动）。

- **形态**：`document.body` 下的 portal 单例 `div#friend-preview`（含一张 `img`），**白边 2px 圆角大图**（`border-radius: 16px`，`16/10`，`width: min(360px, 42vw)`），复用 `float-panel` 令牌、适配亮/暗色。
- **触发条件**：仅桌面 `(hover: hover) and (pointer: fine)`；移动端 CSS 直接 `display: none`。
- **数据来源**：`public/assets/friends-shots/{entry.id}.webp`——`friends.astro` 构建期用 `shotExists()` 判断文件是否存在，存在才把路径塞进卡片 `data-screenshot`；无截图时卡片加 `friend-card--no-shot`、不弹预览（优雅降级）。
- **定位**：优先卡片右侧 → 左侧 → 上方 → 下方 → 居中兜底，且夹取在视口留白内；`scroll` / `resize` 时隐藏或重定位。
- **单例守卫**：`window.__friendPreviewReady`；`swup:willReplaceContent` 时 `hidePreview`。

## 四、支撑系统（GitHub Actions）

### 1. 友链状态检测（`friend-status.yml`）

- **触发**：每天 `17 5 * * *`（5:17，避开整点）+ `workflow_dispatch`。
- **脚本**：`node scripts/友链状态检测/index.mjs`。
- **逻辑**：正则读各 `siteurl`，逐个 `HEAD` 请求测响应时间；HEAD 失败（部分站点不支持）退化 `GET`。
- **分档阈值（ms）**：`FAST = 800`、`SLOW = 3000`、`TIMEOUT = 8000`；档位 `fast` / `ok` / `slow` / `down`。
- **产物**：`public/friends-status.json`（`{ timestamp, sites: { <siteurl>: { status, ms } } }`），由 Action 提交回仓库。

### 2. 友链站点截图（`friend-screenshots.yml`）

- **触发**：每周日 `23 3 * * 0`（3:23）+ `workflow_dispatch` + push 变更 `src/content/friends/**` 时自动跑（workflow 配置分支为 `lh`）。
- **脚本**：`node scripts/友链截图/index.mjs [友链id] [--force]`。
- **流程**：Playwright `chromium` 无头浏览器，伪装真实浏览器——真实 Chrome UA（避免 `HeadlessChrome` 被反爬）、`locale: zh-CN`、`timezoneId: Asia/Shanghai`、视口 1280×800、`deviceScaleFactor: 2`；`load` 后依次等 `networkidle`（6s 超时兜底）→ 字体就绪 `document.fonts.ready`（5s 兜底）→ 2s 缓冲；PNG 截图经 `sharp` 压到 **640 宽 webp（quality 75）**。
- **重试**：每个站点共 3 次机会（首次 + 2 次重试），全败才算失败。
- **产物**：`public/assets/friends-shots/{id}.webp`，由 Action 提交回仓库。
- **参数**：传友链 id 只截该友链并强制覆盖；`--force` 忽略已存在截图全部重截；已存在且未加 `--force` 时跳过。

> ⚠️ **截图文件名必须与 Astro entry id 完全一致**：Astro glob loader 的 id 走 **github-slugger** 规则（小写 + 移除标点、空格转连字符），仅 `toLowerCase()` 不够——文件名含全角标点时 Astro 会去掉标点（如 `39-胡超，作品集` → `39-胡超作品集`）。脚本已内置 `github-slugger` 生成文件名，与页面 `shotExists()` 对齐；不一致会导致卡片退化为无截图（Windows dev 下含大写文件还会误判存在、引发 404，线上 Linux 直接退化）。

### 3. 状态徽标注入（现状）

页面脚本 `bindStatus()` 仍是：`fetch('/friends-status.json')` → 按 `card.dataset.siteurl` 匹配 → 给 `.friend-status-tag` 注入档位 class 与文案（`down` 显示 `DOWN`，否则显示 `{ms} MS`），**无 JSON 时静默隐藏**。

> 2026-09-30 卡片改版后卡片已无 `.friend-status-tag` 节点，故该注入当前为**空操作**（脚本保留、优雅降级）。状态检测链路本身仍在每天运行

## 概述

音乐集合为全站播放器（`/music` 可视化页面、侧栏悬浮播放器、Dock 音乐入口）提供歌单数据。与其他集合不同，它是**单文件多歌单**的 JSON。

- **物理目录**：`src/content/music/*.json`（当前只有一个 `playlist.json`）
- **集合定义**：`src/content.config.ts` 的 `musicCollection`
- **展示页面/消费点**：`src/pages/music/index.astro`（`/music`，3D 可视化播放页）、`src/components/features/MusicManager.astro`（全站单例 `window.__fireflyMusic`）、侧栏 `Music.astro`、`FloatingDock.astro` / `UnifiedDock.astro`
- 曲目音频、歌词、封面**不存本地**，播放时由 Meting API 按平台歌曲 ID 实时解析

## JSON 结构

```json
{
  "version": 1,
  "updated": "2026-10-08",
  "playlists": [
    {
      "id": "default",
      "name": "博客歌单",
      "songs": [
        { "name": "Always Online", "artist": "林俊杰" },
        { "name": "歌名", "artist": "歌手A / 歌手B", "server": "netease", "id": "123456" }
      ]
    }
  ]
}
```

| 层级 | 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 根 | `version` | number | 否 | `1` | 数据版本 |
| 根 | `updated` | string | 否 | `""` | 歌单最后更新日期（`YYYY-MM-DD`） |
| 根 | `playlists` | array | 是 | — | 歌单列表，可放多个 |
| 歌单 | `id` | string | 是 | — | 歌单唯一标识，如 `default` |
| 歌单 | `name` | string | 是 | — | 歌单显示名 |
| 歌曲 | `name` | string | 是 | — | 歌曲名 |
| 歌曲 | `artist` | string | 是 | — | 歌手名；多人用 ` / ` 分隔（搜索兜底时按斜杠拆分匹配） |
| 歌曲 | `server` | enum | 否 | `netease` | 音乐平台：`netease`（网易云音乐）/ `tencent`（QQ 音乐） |
| 歌曲 | `id` | string | 否 | `""` | 平台歌曲 ID；**留空时运行期按「歌名 + 歌手」搜索兜底** |

## Meting 解析机制

- API 地址配置在 `src/config/musicConfig.ts`（形如 `https://mus.5484826.xyz/api?server=:server&type=:type&id=:id`），不走环境变量
- **有 `id`**：直接请求 `type=song&id=<平台歌曲ID>` 拿到播放地址、歌词、封面
- **无 `id`**：请求 `type=search&id=<歌名> <首位歌手>` 搜索：先要求结果包含指定歌手，匹配不中再用纯歌名搜第二次
- 解析在用户点播放时**懒执行**，结果在 localStorage 缓存 30 天；`http://` 链接自动升级为 `https://`
- 想让某首歌秒开且结果稳定，建议去网易云/QQ 音乐复制歌曲 ID 填进 `id` 字段，而不是依赖搜索

## 维护方式

- 日常加歌：直接编辑 `src/content/music/playlist.json`，往对应歌单的 `songs` 里追加 `{ name, artist }` 即可

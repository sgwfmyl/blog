本文档讲解博客的**管理员登录与私密模块**：如何区分管理员与游客、密码登录认证、私密内容如何从远端私有仓库按需动态加载（**不进入部署产物**，保障数据安全）、以及私密元数据如何融合进公开视图（归档、分类、标签、统计图表、导航）。

- **功能域**：`src/components/security/`、`src/components/controls/`、`src/components/widget/`、`src/utils/`（auth / private-meta-store / private-renderer）、`src/pages/private/`
- **运行时**：Cloudflare Worker（`worker/index.ts`，处理 `/api/*` 与 `/private/*` 壳回退）
- **私密仓库**：`sgwfmyl/blog-private`（私有 GitHub 仓库，Contents Read-only 令牌访问）
- **版本演进**：v1.63.0 登录模块 → v1.64.0 内容融合 → v1.65.0 图表统计融合 → v1.65.1 性能优化 → v1.65.2 同路径镜像

***

## 一、模块概述

- **身份区分**：游客 / 管理员。管理员通过**纯密码登录**，无需账号体系；7 天免输（HttpOnly 签名 Cookie）。
- **动态加载**：私密内容（导航条目、文章页面、元数据）**不参与静态构建**，登录后由 Worker 实时从私有仓库拉取，经 KV 缓存 5 分钟；未登录的游客请求不到任何实际内容。游客抓取 dist 部署产物也拿不到（安全红线）。
- **视图融合**：登录后私密条目自动并入**归档页、最近更新、侧栏分类/标签、分类文件夹树、热力图、标签图谱、分类玫瑰图、文章目录、日历、侧栏统计、导航页**，登出即回退公开基线。
- **同路径镜像**：私密内容可复用公开路径（如 `/posts/私密/日记/`），登录后直接按公开 URL 访问，复用公开文章页排版。
- **入口**：页面「管理」按钮（坞站 / 移动端菜单）弹出密码框；`/private/` 为私密空间（列表 / 详情）。

## 二、请求链路

1. 站点加载 → `AuthManager` 初始化 → `GET /api/auth/me` → 返回 `{"ok":true,"admin":false}`（未登录态）。
2. 点击「管理」→ `AuthModal` 弹窗 → `POST /api/auth/login`，密码经常量时间比较通过后签发 HttpOnly 会话 Cookie（`blog_admin`，7 天有效）。
3. 登录后 `private-meta-store` 自动拉取 `GET /api/private/meta`（私密条目元数据），登录态变为 false 时自动清空。
4. 访问 `/private/`：Worker 将 `/private/*` 回退到**静态壳页**（仅登录门 + 加载脚本），页面脚本按 pathname 提取 slug，携带 Cookie 请求 `GET /api/private/pages`（列表）或 `GET /api/private/pages/<slug>`（详情）。
5. 访问公开文章路径（已配置镜像映射）：Worker 查询 `routes.json`，命中私密映射时只返回**不含内容的 noindex 壳**；管理员确认身份后才经 `GET /api/private/route?path=<pathname>` 请求受保护正文。
6. Worker 用 `GH_PAT` 调 GitHub Contents API 拉取私有仓库文件，KV 缓存 5 分钟；返回内容由 `private-renderer`（marked + DOMParser 白名单消毒）渲染，动态剥离 Content Collection 的 YAML frontmatter 复用公开排版。
7. 导航页（`/projects/`）登录后自动合并 `nav.json` 条目注入导航列表。

### Worker API 一览

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/api/auth/login` | 密码登录，签发会话 Cookie | 公开（限流） |
| POST | `/api/auth/logout` | 注销，清除 Cookie | 可选 |
| GET | `/api/auth/me` | 当前登录态 | 公开 |
| GET | `/api/private/route?path=<pathname>` | 同路径镜像：查 routes.json 映射并返回正文（v1.65.2） | 需登录 |
| GET | `/api/private/nav` | 私密导航条目（`nav.json`） | 需登录 |
| GET | `/api/private/meta` | 私密条目元数据（`meta.json`，融合公开视图用，v1.64.0） | 需登录 |
| GET | `/api/private/pages` | 私密页面列表（`pages/index.json`） | 需登录 |
| GET | `/api/private/pages/<slug>` | 私密页面详情（`pages/<slug>.md`） | 需登录 |
| GET | `/private/*` | 静态壳页（登录门 + 加载脚本） | 公开 |

### 安全设计

- **密码比较**：`timingSafeEqual` 常量时间比较，防时序侧信道。
- **会话**：HMAC-SHA256 签名 + HttpOnly + Secure + SameSite=Lax，7 天有效。
- **限流**：按客户端 IP 在 KV 计数，5 次失败冷却 30 秒（键 `rl:<ip>`）。
- **隐私**：未登录不发起任何私密内容请求；私密元数据本地缓存**仅在 auth 确认管理员时读取/写入**，游客绝不接触缓存，避免残留私密标题泄露；sitemap 已排除 `/private`；页面 `noindex, nofollow`。
- **slug 校验**：允许中文/子目录路径（如 `私密/观影记录`），但拦截 `..` 路径穿越与非法字符（`SLUG_PATTERN`）。

## 三、密钥与环境变量

| 变量 | 说明 |
| --- | --- |
| `ADMIN_PASSWORD` | 管理员登录密码（纯密码） |
| `AUTH_SECRET` | 会话签名密钥（随机 32 字节 hex） |
| `GH_PAT` | 私有仓库 Contents Read-only 令牌 |
| `GH_OWNER` | 私密仓库归属（`sgwfmyl`） |
| `GH_REPO` | 私密仓库名（`blog-private`） |

配置位置：

- **本地开发**：根目录 `.dev.vars`（已被 gitignore，模板见 `.dev.vars.example`）。
- **线上**：仓库 **Settings → Secrets and variables → Actions**，由 `.github/workflows/deploy.yml` 注入 `wrangler-action` 上传为 Worker Secrets。
- **KV 绑定**：`wrangler.toml` 中的 `ADMIN_KV`（限流计数 + GitHub 内容缓存）。
- 修改密码 / 密钥后需**重新触发部署**（推送 `lh` 分支触发 `deploy.yml`）。

## 四、私密仓库内容规范（`blog-private`）

```
private/
├── nav.json            # 导航页合并的私密条目
├── meta.json           # 私密条目元数据（融合归档/统计/图表用，v1.64.0）
├── routes.json         # 同路径镜像路由清单（v1.65.2）
└── pages/
    ├── index.json      # 私密页面列表
    └── <slug>.md       # 私密页面正文（Markdown）
```

**`nav.json`**（数组，字段与导航集合对齐）：

```json
[
  {
    "name": "私密站点示例",
    "url": "https://example.com",
    "icon": "",
    "description": "登录后在导航页合并显示的隐藏条目",
    "tags": ["示例", "私密"],
    "category": "私密收藏"
  }
]
```

**`meta.json`**（数组，私密条目元数据；`type` 与公开归档对齐，融合进公开视图时按此分派）：

```json
[
  { "slug": "hello", "type": "post", "title": "私密文章示例", "date": "2026-10-14", "tags": ["示例", "私密"], "category": "私密" },
  { "slug": "私密/观影记录", "type": "bangumi", "title": "私密观影记录", "date": "2026-10-15", "tags": ["观影"], "category": "私密" }
]
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `slug` | ✅ | 详情标识，可含子目录路径（对应 `pages/<slug>.md`，路径式 slug v1.64.0） |
| `type` | ✅ | `post` / `moment` / `bangumi` / `life`，与公开归档类型对齐 |
| `title` | ✅ | 标题 |
| `date` | ✅ | ISO 日期（可含时间），用于归档分组与排序 |
| `tags` | ✅ | 标签数组，融合标签云/图谱 |
| `category` | ❌ | 分类路径（可含 `/`），缺省空串；建议使用与公开分类不冲突的命名（如「私密」） |
| `url` | ❌ | 可选详情页 URL，缺省 `/private/<slug>/` |

**`routes.json`**（对象，`routes` 数组；`pathname` 为公开 URL，`source` 为私有仓库中同路径的 Content Collection Markdown）：

```json
{
  "routes": [
    { "pathname": "/posts/私密/日记/", "source": "src/content/posts/私密/日记.md" }
  ]
}
```

**`pages/index.json`**（数组，`slug` 对应 `pages/<slug>.md` 文件名，不带扩展名）：

```json
[
  { "slug": "hello", "title": "私密文章示例", "date": "2026-10-14" }
]
```

**`pages/<slug>.md`**：私密页面正文（Markdown）。同路径镜像场景可保留公开 Content Collection 的 YAML frontmatter，动态渲染会自动剥离该段并复用公开文章的标题、正文、目录及主题排版（v1.65.2）。

## 六、性能与缓存策略（v1.65.1）

针对「私密数据出现慢 + 刷新卡顿」的优化，核心是 **localStorage stale-while-revalidate 缓存 + 数据指纹去重**：

- **缓存秒出**：`private-meta-store` 在 auth 确认为管理员后，先同步恢复 localStorage 缓存（键 `firefly:private-meta:v1`，TTL 60s）立即渲染，再后台拉取最新覆盖。缓存**仅在管理员确认登录后读写**，游客不接触缓存、不发起私密请求。
- **指纹去重（store 层）**：`notifyIfChanged` 仅在数据 JSON 指纹变化时通知订阅者，相同数据不再触发组件重绘；401/数据异常时清缓存降级为公开基线，网络异常时保留缓存兜底。
- **指纹去重（组件层）**：图表/统计组件内联脚本各自维护 `lastMergedJson` / `lastGraphJson` 指纹：
  - `PostDirectoryList` 按 slug/title/date 指纹判断私密数据是否变化，未变化时跳过「移除+重建+重绑手风琴」，避免刷新时手风琴展开状态被重置。
  - `CategoryRose` 合并数据未变化时跳过列表重建与 `chart.setOption`。
  - `TagGraph` 图谱数据未变化时跳过 `data-graph` 更新与图谱销毁重建。
  - 订阅触发与 SPA 导航重执行都会调用 applyMerge，靠指纹保证只重绘一次（幂等：公开基线从 `data-*` 属性读取且不回写）。

## 七、运维 FAQ

- **新增私密内容**：编辑 `blog-private` 仓库对应文件并 push，线上约 5 分钟（KV 缓存 TTL）后生效；若希望公开视图（归档/统计）立即并入，需在 `meta.json` 同步登记。
- **新增同路径镜像**：在 `routes.json` 增加 `{pathname, source}` 映射并 push，正文文件放到私有仓库相同 `source` 路径。
- **更换密码**：更新 Actions Secret `ADMIN_PASSWORD` 与本地 `.dev.vars` → 重新部署。
- **`/api/private/*` 返回 404/403**：GitHub 对无权限的私有仓库统一回 404。先本地用 `GH_PAT` 直测 `https://api.github.com/repos/<GH_OWNER>/<GH_REPO>` 确认令牌权限（Contents Read-only）与仓库名正确；注意编辑 fine-grained PAT 的授权范围不会改变令牌字符串，无需重新配置 Secret。
- **私密数据不刷新 / 卡顿**：确认已部署 v1.65.1 以上；浏览器 localStorage 中 `firefly:private-meta:v1` 为正常缓存，登出会自动清除；若怀疑旧缓存，可在登录后强制刷新（`Ctrl+F5`）。
- **开发调试**：本地 `pnpm dev` + `wrangler dev`（需 `.dev.vars` 填全），访问 `/private/` 走 Worker 代理。

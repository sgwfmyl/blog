Waline 是一款轻量、简洁、安全、可免费部署的评论系统，适合用于静态博客、个人站点、文档站以及轻量级内容社区。它强调“低成本部署 + 免费可用 + 快速集成”，其官方定位是兼顾 Markdown 评论写作体验、评论展示、用户登录、文章互动与数据存储的评论基础设施。

- 轻量：完整客户端约 53KB（gzip）。
- 完全免费部署：可以通过 Vercel 免费部署。
- 易于部署：支持多种部署方式，多种数据库服务支持。
- 登录支持：在允许匿名评论的基础上，支持账号注册和身份识别。

## 1. 核心能力

### 1.1. 评论语法支持

Waline 对评论内容支持完整的 CommonMark 标准 Markdown，同时加入 Github 风格扩展：

并且支持在安全机制允许的前提下嵌入 HTML 内容。也就是说，评论内容并不局限于纯 Markdown，既具备富文本写作能力，也具有一定的 HTML 扩展能力。

### 1.2. 安全机制

Waline 的评论能力和安全能力紧密绑定。服务端在接收原始评论后，会进行 Markdown 解析、代码高亮、公式渲染、XSS 清理等过程，保证评论内容在评论区中安全呈现，而非原文直接输出。这可以降低评论区注入脚本、恶意 HTML、危险标签等引发的安全隐患。

### 1.3. 预览限制       

官方客户端 `@waline/client` 采用轻量级 Markdown 解析器，以减小客户端体积。这导致预览面板与最终展示存在一定限制：

- 标准 Emoji 语法如 `:tada:` 在预览面板中可能无法正确显示。
- 上下角标语法如 `H~2~O`、`x^2^` 在预览中可能无法正确渲染。
- TeX 公式语法如 `$a = 1$` 在预览中默认无法渲染。

所以，评论区前端预览和后端服务端最终渲染并不总是完全一致，用户应以服务端真实输出为准。

## 2. 技术实现架构

从文档中的描述看，Waline 的实现架构可以理解为“前端轻量客户端 + 服务端 Markdown 渲染 + 存储服务”三段式：

1. 前端客户端 `@waline/client`：负责评论输入、预览、评论展示、文章交互、用户交互等。
2. 服务端：接收评论原文，执行 Markdown 渲染、代码高亮、TeX 渲染与 XSS 清理，并返回安全 HTML。
3. 存储服务：将评论内容保存在对应数据库中，供后续页面查询、展示、管理、通知等功能使用。

这套架构体现了 Waline 的设计思路：客户端尽量小巧，服务端负责真正的安全渲染与存储，保证展示效果适合博客和静态站点场景。

## 3. 适用场景

Waline 非常适合以下场景：

- 个人博客和技术博客。
- 静态站点评论系统。
- 文章或文档站点的评论入口。
- 轻量级社区或知识库页面的互动功能。

它的优势在于：

- 不强依赖重型前端框架。
- 配置简单。
- 支持灵活部署。
- 支持 Markdown 语法，适合技术内容的发表评论场景。

## 4. 部署方式

Waline 支持多种部署形式，常见包括：

- Vercel 免费部署。
- CloudBase 等云开发平台部署。
- Netlify、Railway、Zeabur 等平台部署。
- 独立 VPS 部署。
- 通过多数据库方案接入不同系统。

从工程实践角度，部署 Waline 主要分两步：

1. 在服务端部署 Waline 的评论后端，实现数据库、API、Markdown 渲染与安全处理。
2. 在博客或站点前端接入 `@waline/client`，通过 `serverURL` 等配置，让页面具备评论能力。

因此 Waline 既可以看成“博客评论组件”，也可以看成“评论后端系统”。

## 5. 生态与扩展

Waline 还包含了额外能力，例如：

- 自定义 Emoji 表情包。
- 评论通知系统。
- 文章反应。
- 浏览量统计。
- 评论数统计。
- 多语言支持。
- 自定义样式与主题能力。

如果站点要求精细化评论体验，还可以借助自定义渲染器 `texRenderer` 与 `highlighter`，让预览环境更贴近最终展示效果。

## 6. 总结

Waline 的本质是一款面向博客和静态站点的轻量评论系统。它的核心价值在于：

- 低门槛部署
- 免费使用
- Markdown 语法支持
- 服务端安全渲染
- 适合技术内容的评论场景

如果站点想要“博客式评论区、支持 Markdown、便于部署、无需重型平台支持”，Waline 是一个非常值得考虑的方案。

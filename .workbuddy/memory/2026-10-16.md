## 补充：岛屿/Server Islands 认知澄清 + 归档页取舍定稿

- 站长提出「astro 岛屿分客户端和服务端，据数据安全性取舍」——术语校正：普通 Islands（client:*，客户端水合，公开数据）vs Server Islands（server:defer，服务端渲染，私有数据不下发）。Server Islands 只能在 prerender=false/output:server 页面上用，不能在 output:static 页打补丁。
- 澄清 4 个误解（已写入方案文档 8.3 节）：
  1. 同一 URL 不可能「未登录静态、登录后动态」（prerender 构建期定死）
  2. 私有内容必须 no-store 不缓存，不存在「登录时缓存、第一次卡顿」——安全代价
  3. Server Islands 不能把静态页变动态
  4. 登出回归靠「清 Cookie + 清 Swup 缓存 + pageshow bfcache 刷新」
- 归档/目录合并私有的安全 vs 性能取舍：**选安全**（归档页改 prerender=false，登录后服务端合并私有，no-store）。已写入 8.1 决策表。

## 补充：方案定稿 + 4 个实现补强点落地

- 最终拍板：**私有 URL 采用独立前缀**（如 /diary/），不做 posts 同前缀。理由：Astro 文件路由的 prerender 是文件级而非 slug 级，同前缀「部分静态部分动态」不可行，只能整前缀改 SSR（牺牲公开文章静态优势）。「结构统一」= 数据源统一，≠ URL 前缀统一。
- 4 个实现补强点（已写入方案文档 8.4 节）：
  1. getPrivateMeta 区分「异常」vs「无匹配」——新增 getPrivateMetaStrict()（抛错），/api/private/meta.ts 改用 strict + 上游异常返 503
  2. Vary: Cookie 定位是「防御性冗余」，不能替代 no-store
  3. 登出接口需补 CSRF（SameSite + token/同源校验），不止 POST+来源
  4. X-Robots-Tag noindex 防「偶发 URL 泄露被收录」，不是防 sitemap
- 代码改动：private-source.ts 新增 getPrivateMetaStrict()（getPrivateMeta 保留静默降级供公开场景）；api/private/meta.ts 改用 strict + 503。

## SSG + KV 方案决策 + 测试 2 链路验证

- 站长决定采用 **SSG（构建期预渲染）+ 数据存 KV + 运行时鉴权**，替代「运行时渲染」。核心：markdown 渲染搬到构建期（Node，无体积限制，保留 shiki 高亮），worker 运行时只做「D1 鉴权 + 读 KV 返回 HTML」，体积从 60MB 降到几 MB。
- 澄清安全边界：SSG + KV 仍是「鉴权」本质（未登录 404），安全不降低；「渲染时机」与「鉴权」可解耦。唯一代价：私有内容更新需重新构建。
- **测试 2 链路验证（全部通过）**：
  - 私有仓库 `sgwfmyl/blog-private`（private，main）可经 gh api 访问
  - `private/meta.json` 是**数组**格式（3 条记录），非方案文档写的 `{items:[...]}` 包裹 → 需修正文档
  - `wrangler kv key put --binding=ADMIN_KV --remote` 成功写线上 KV，`get --remote` 读回正确
  - 坑：`wrangler kv key put` 默认写 local，必须 `--remote` 才写线上
  - CI 写 KV 需 CLOUDFLARE_API_TOKEN 有 KV 写权限（当前是 Edit Cloudflare Workers，需确认）
- 现有代码影响：阶段 1-3（鉴权/数据源/合并）基本不动；要改的是「渲染器从运行时搬到构建期」+ 新增「构建期预渲染脚本」+ SSR 路由改为「读 KV」。
